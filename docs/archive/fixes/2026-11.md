# Recent Critical Fixes — November 2026

## 0. The nightly memory job never ran the suite to the end

**Symptom.** From 2026-09-17 to 2026-11-13 the `Memory Leak Detection` job of
`.github/workflows/stress-tests.yml` failed every night and opened a new
`Nightly memory profiling run failed` issue each time: 56 identical issues
(#576 and its duplicates). The date matters. PR #573 had fixed the artifact
upload and added the gate that fails the job when `pytest --memray` fails, so
from the next night on the job reported its real outcome. The profiled run had
never passed. #573 only made that visible.

**No leak was measured.** Every run died at about 90% of the suite in one of two
ways:

- **Timeout** (most nights).
  `tests/ui/dialogs/test_block_detail_dialog_extended.py::test_block_detail_dialog_init_int_day`
  hung until `pytest-timeout` (300 s, `thread` method) killed the process. The
  main-thread stack ended in `tkinter.Misc._root()`:
  `while w.master is not None: w = w.master`, with every `.master` produced by
  `unittest.mock`.
- **Abort** (#576, #620, #660). `Fatal Python error: Aborted` in
  `tests/ui/components/test_single_video_workflow_ui.py`. The thread that hit
  the abort was a `Camera._reader_thread`, in the middle of a garbage collection.

**Root cause 1: the job had no display.** `ci.yml` and the `mutation-catalogue`
job run the suite under `xvfb-run`. The memory job did not. Without a display,
`tests/conftest.py` sets `HEADLESS_TESTS = True` and the Tk root becomes
`_create_mock_tk_root()`, a `MagicMock`. CI never runs in that mode. The mock
had no `master = None`, so `root.master` returned a fresh mock, whose `.master`
was another mock, and so on without end. Any widget built over it looped forever
in `_root()`. This reproduces locally:
`ZEBTRACK_HEADLESS_TESTS=1 pytest <that test> --timeout=20` hangs, and the same
test passes in 9 s on a real Tk.

**Root cause 2: three tests leaked camera reader threads.** `Camera.__init__`
starts `_reader_thread`. Three tests in `tests/test_io_sources.py` built a camera
over a mocked `cv2.VideoCapture` that returns `(True, MagicMock())` forever, and
never called `release()`. Those threads spun through the rest of the session,
allocating mocks. The thread dumps of every failed run show exactly these three
threads. Under memray their allocations triggered garbage collection on that
thread, and when the collection finalized Tk objects off the main thread, Tcl
aborted the process. The 2026-09 investigation could not find these threads
because it measured the wrong test directories.

**Fix.**

- The memory job installs `xvfb ffmpeg libavcodec-extra` and builds the template
  archive and the translations, as `mutation-catalogue` does. It then runs
  `pytest --memray` under `xvfb-run`.
- `_create_mock_tk_root()` sets `root.master = None`, so headless mode can no
  longer hang. Guarded by `tests/test_conftest_headless_root.py`.
- The three tests release the camera in a `finally` block. The first one now
  asserts that the reader thread is dead after `release()`.
- `stress-tests.yml` opens each nightly issue at most once. The shared helper
  `.github/scripts/file_nightly_issue.js` comments on the open issue with the
  same title when there is one, so a persistent failure keeps a single history.

**Still open (not this fix).** The `threading-stress` and `flakiness-detection`
jobs pass `--count=N`, but `pytest-repeat` is not installed. Both die on
`unrecognized arguments: --count` without running a single test, and
`continue-on-error: true` reports them as green. #625 was the one night the
threading job went red, and only because PyPI dropped the connection during
`poetry install`.
