# Recent Critical Fixes — August 2026

## 0. Segmentation returned the whole screen: the "exactly one mask" gate

**Symptom (2026-08-31, `cest_9.mp4`).** The operator selected `Aquarium AI: seg`
and "preserve the real shape", ran auto-detect on a pre-recorded single video,
and got an arena of 1189×720 on a 1280×720 frame — effectively the whole frame.

**The configuration was never the problem.** `logs/analysis.log` shows the policy
resolving correctly and the segmentation weight loading:

```json
{"method":"seg","preserve_real_shape":true,"uses_masks":true,"event":"arena_detection_policy.resolved"}
{"name":"best_seg_lateral.pt","event":"weights.get_path.selected"}
{"mask_index":0,"class_id":0,"num_points":413,"bbox":[4,0,1194,720]}
{"mask_index":1,"class_id":0,"num_points":4,"area":0,"bbox":[76,720,1042,720]}
{"num_masks":2,"expected":1,"event":"aquarium_detector.wrong_mask_count"}
{"event":"aquarium_detector.mask_unavailable_fallback"}
{"points":4,"event":"processing_coordinator.aquarium_detection.single_success"}
```

**Root cause.** `_process_segmentation_results` accepted a frame only when the
model returned **exactly one** mask. YOLO returned two: the tank (413 vertices,
0.928) and a zero-height sliver on the bottom edge (0.272). The gate discarded
both, the caller degraded to `_extract_polygon_from_detection`, and that path
never reaches `_shape_segmentation_polygon` — so `preserve_real_shape` was
ignored by construction. It repeated on all four analysed frames, and consensus
"confirmed" the rectangle at IoU 0.997.

The live flow never had this bug: `_burst_pass` picks the best box index and
reads `masks.xy[best_idx]`, tolerating any number of detections.

**Fix.** The selection rule now lives in
`core/detection/arena_candidate_selection.py` and is shared by both flows.
Degenerate outlines (fewer than 3 vertices, or a zero-area bounding box) are
filtered; among the survivors the mask at the highest-confidence box that passes
the area gate wins.

**Four related defects fixed in the same pass:**

1. **Consensus mixed populations.** Mask outlines and bbox fallbacks went into
   one IoU pool. Rectangles agree with each other at ~0.99 while real outlines
   jitter, so a single degraded frame out-voted the preserved shapes. Consensus
   now runs over masks *or* boxes, never both.
2. **The low-confidence retry had no class filter and no area ceiling** — it
   predicted without `classes=[0]` and accepted anything above 10% of the frame,
   a second route to "the arena is the screen".
3. **Two aquariums could not preserve a shape at all.** `detect_multiple_aquariums`
   was box-only and did not even accept `preserve_real_shape`.
4. **Failure was silent.** An empty detection logged a warning and changed
   nothing on screen. It now tells the user, as does a run that degraded to a
   rectangle after segmentation was requested.

**Note on the 80% placeholder.** `_find_consensus_polygon` fabricates a
frame-sized rectangle when nothing is detected, guarded by
`hasattr(source, "_cap")` — and `VideoFileSource` exposes `cap`. The branch is
therefore unreachable with a real video and was deliberately **not** activated:
handing back a fabricated arena is worse than reporting failure.
`get_last_detection_provenance()` tags it `synthetic_default` if it ever fires,
and `tests/test_aquarium_detector.py` pins the current behaviour so a rename
cannot switch it on by accident.

**Guarded by.** `tests/core/test_arena_candidate_selection.py`, the multi-mask
and consensus classes in `tests/test_aquarium_detector.py`, and 10 entries in
`scripts/mutation_catalog.yaml` (four of which survived the first run).

## 1. Longitudinal projects: the video stem is not a unique key

**Symptom.** A partial report over 6 selected videos produced 3 rows. The Word
report showed `n=2` / `n=1` instead of `n=4` / `n=2`, and every row was labelled
`Day01` — day 2 had vanished entirely.

**Root cause.** `VideoManager.find_video_entry` tested `path` and
`experiment_id` in the *same* loop iteration:

```python
for _batch, video in iter_project_videos(project_data):
    if candidate_path and normalized_target:
        if normalize_path(candidate_path) == normalized_target:
            return video          # only matches THIS list item
    if experiment_id:             # but this runs on EVERY item
        if stem(candidate_path) == experiment_id:
            return video          # returns the first homonym
```

A longitudinal project films the same subject every day, so
`Dia_1/CECT_4/CECT_4.mp4` and `Dia_2/CECT_4/CECT_4.mp4` share the stem
`CECT_4` (entries carry `experiment_id: null`, so the stem is the fallback id).
Asking for day 2 returned day 1's entry, because the scan hit day 1 first and
the stem fallback fired before the path scan ever reached day 2.

**Blast radius.** `resolve_results_directory` calls the metadata lookup to build
`<project>/Grupo_X/Dia_Y/Sujeito_Z/`, so day 2's `_summary.parquet` was written
into day 1's folder, **overwriting it**. The trajectory and the individual
`.docx`/`.xlsx` landed correctly, because those call sites pass `metadata=`
explicitly — only the summary diverged. Last write won, so which day survived
depended on processing order.

Then the unified report read those 3 files twice (once per selected video),
stamped all 6 rows with day 1's metadata, and `drop_duplicates()` over every
column silently collapsed them back to 3.

### Fixes

- **`VideoManager.find_video_entry`** — `path` and `experiment_id` are now
  scanned in **separate passes**, path first. The stem fallback is reached only
  when the path is unknown to the project (single-video flows, unregistered live
  sessions, stale paths after a project move).
- **`OutputRegistrationManager.resolve_results_directory`** — forwards
  `video_path` to the metadata lookup instead of querying by the ambiguous stem.
  Call sites that pass `metadata=` explicitly (every live-session path) are
  unaffected: the lookup never runs for them.
- **`UnifiedReportMixin`** — dedup moved from row content to **summary path**.
  Two different videos resolving to the same summary file are now refused and
  reported to the user (`workflow.unified_report.summary_path_collision`)
  instead of being quietly merged. Duplicate entries in the *selection* are
  still dropped silently, since that is redundancy rather than an anomaly.

### The rule

**Never key a video on its basename when a path is available.** The stem is
unique only within one day of one project. `experiment_id` is a *fallback for
unregistered paths*, never a primary lookup key — and it must never decide a
directory that gets written to.

`drop_duplicates()` over all columns is likewise never the right tool on
summary rows: it cannot distinguish "the same file read twice" from "two
animals with identical metrics", and choosing wrong deletes real subjects
without a word in the log.

### Regression tests

- `tests/core/test_video_manager_basic.py` — path beats a repeated stem; the
  stem fallback still works for unregistered paths.
- `tests/core/project/test_output_registration_manager_extended.py` —
  `video_path` reaches the lookup; explicit `metadata=` skips it.
- `tests/coordinators/test_unified_report.py::TestLongitudinalSubjectCollisions`
  — both days reach the report; a shared summary warns; identical metrics across
  distinct animals are kept.
