# F6 — ui-editors (part 1): fragments for F7

Front F6 part 1 (`feat/v8-ui-editors`) adds the analysis-window editor, the
Barnes-maze and legacy-trigger presets, the wizard template schema v4 and the
`ANALYSIS_WINDOW_SPEC_CHANGED` event. The class-role panel is part 2 (after F2).
F7 owns `CHANGELOG.md`, `TEST_MAP.md`, `CLAUDE.md` and the locales; the text
below is ready to paste. Every new user-visible string is in `_()` and still
needs its pt_BR msgstr.

## CHANGELOG fragment (under `## [8.0.0]` → `### Added`)

```markdown
- **Editor de janela de análise na aba Zonas** (`ui/components/analysis_window_panel.py`,
  ADR-011). Um painel na coluna esquerda da aba Configuração de Zonas mostra, em
  texto corrido, quando a análise COMEÇA e quando TERMINA, e abre um editor de
  linhas tipadas: classe presente/ausente (por nome ou papel), "mantida por" N
  segundos ou quadros, sujeito entra/sai de uma ROI do projeto, tempo do vídeo,
  número do quadro, tempo após o início (só no fim), sinal do Arduino com código,
  sinal manual e fim do vídeo (só no fim). Cada bloco combina as linhas por "todas",
  "qualquer uma" ou "em sequência"; as opções "se o início nunca acontecer" (usar a
  gravação inteira ou deixar as métricas vazias) e "quando o fim acontecer" (só
  marcar ou encerrar a sessão ao vivo) completam a regra. Erros de validação viram
  frases com o bloco e a linha. A regra fica em `project_data["analysis_window"]`
  (`None` = gravação inteira); uma regra escrita à mão que o editor não sabe mostrar
  é descrita e preservada até alguém salvar outra.
- **Predefinição "labirinto de Barnes"** (`core/conditions/presets.py`): início
  quando a caixa de partida e o experimentador somem e o rato aparece, por 5 quadros
  seguidos; fim no primeiro de fim do vídeo, rato ausente por 3 s ou 240 s após o
  início. A spec é a de aceitação da v8 (com 3 quadros e 2 s ela reproduz a fixture
  de testes, mesmo hash).
- **Templates do wizard na versão 4**: guardam a janela de análise. Um template v3
  com "Modo de Gatilho Externo" ligado é convertido ao carregar em uma janela
  equivalente (código 1 do Arduino inicia, código 0 para e encerra a sessão ao vivo),
  com aviso na etapa de confirmação, e a janela chega ao `project_config.json` do
  projeto criado. O checkbox legado continua na etapa ao vivo, agora com uma dica
  apontando para o editor de janela.
```

## Events

`UIEvents.ANALYSIS_WINDOW_SPEC_CHANGED` → `payloads.AnalysisWindowSpecChangedPayload(spec,
spec_hash)`. Published by `AnalysisWindowPanel.save()`; subscribed by
`EventDispatcher._on_analysis_window_spec_changed` (status bar: "run the analysis again to
apply it"). Documented in `docs/reference/events.md` §3.3 and
`docs/reference/system_integration.md` §3.8. F4b/F5 may subscribe to invalidate caches
or re-arm a live runtime.

## Contract notes for F4b / F5 / F7

- `project_data["analysis_window"]` is `WindowSpec.model_dump(mode="json", by_alias=True)`
  (`"class"`, not `"class_name"`) or `None`. New projects always carry the key
  (`None` by default); F2's `apply_project_migrations` backfills it for 7.2 projects.
- Wizard → project: `analysis_window` passes the `prepare_controller_parameters`
  allowlist and `ProjectLifecycleManager.create_new_project(analysis_window=None)`
  stores it as given. Validation happens earlier, in `migrate_template` (the only
  source of a wizard-side window today). The F6 diff in `core/project/` is three
  added lines plus two comments, kept minimal for F2's merge.
- A converted v3 template turns `external_trigger_mode` OFF: ADR-011 makes "both
  configured" invalid. The live gate (F5) must therefore honour
  `External(arduino)` in the window, or a converted project records without waiting.
  The LiveConfigStep checkbox is still there, so a user can re-tick it after loading
  a converted template; F5's gate should flag that combination.
- `external_trigger_preset()` uses `on_stop="end_session"` to keep the legacy meaning
  "code 0 ends the recording".
- Class names in the editor come from an injected `class_names_provider`
  (`Callable[[], list[str]]`); `tab_builder` passes none yet, so class lines are free
  text. Part 2 wires it to the active weight's class names.
- New msgids (all English source) live in `analysis_window_panel.py`,
  `templates.py` (`template_migration_note_text`), `confirmation_step.py`,
  `live_config_step.py` (`analysis_window_hint`) and `event_dispatcher.py`.
