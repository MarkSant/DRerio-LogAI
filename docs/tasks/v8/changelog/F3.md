## CHANGELOG — 8.0.0

### Added

- **`3c_Objetos_<base>.parquet` (ADR-010).** One file per video, next to the trajectory (per
  `aquarium_N/` folder in multi-aquarium). For every processed frame it holds one heartbeat row
  (`class_id = -1`, `role = "frame"`, no bbox), even when nothing was detected, plus one row per
  subject and context detection. Columns, fixed order, additions only: `frame:int64,
  timestamp:float64, t_event_s:float64, class_id:int16, class_name:dictionary<string>,
  role:dictionary<string>, x1, y1, x2, y2:float32, confidence:float32, track_id:int64,
  aquarium_id:int16`. Coordinates are raw video pixels, never calibrated. Parquet key-value
  metadata: `zebtrack.objects_schema=1`, `class_names`, `class_roles`, `weight_sha256`, `clock`
  (`pts` | `capture_perf`), `analysis_interval_frames`, plus `class_roles_source`.
  Written by default; `recorder.persist_object_sidecar: false` switches it off.
- `core/services/object_capture.should_capture_objects()`: the single rule for writing the
  sidecar. Only a boolean `True` turns it on (every real `Settings` has it by default).
- `io/object_sidecar.py`: schema, metadata, `resolve_object_sidecar()`,
  `read_object_sidecar()` (validates; a missing, corrupted or incompatible file is `None` with a
  warning, never an exception), multi-aquarium routing and the set of files that travel with a
  trajectory.
- Multi-aquarium: subject rows go only to their own aquarium; context rows go to the aquarium
  that contains their centroid, or to every aquarium with `aquarium_id = null` when they lie in
  none. The same object seen by two aquarium crops is kept once.
- The session output list labels `3c_Objetos_` ("detected objects per frame") and
  `7_AnalysisWindow_` ("analysis window"), in pipeline order. The labels are now translatable.

### Changed

- The pre-recorded worker writes the object sidecar on every processed frame. Before, nothing
  was written for a frame with no detection, so "absent" and "not processed" looked the same.
- Importing a trajectory from the wizard also copies its `3b_Mascaras_`, `3c_Objetos_`,
  `6_FrameLedger_` (csv, parquet, anchor) and `7_AnalysisWindow_` files, renamed to the
  destination base. Sidecars already next to the overwritten trajectory are removed.

### Fixed

- **Reprocessing reused a stale `3b_Mascaras_`.** `start_recording` kept the mask sidecar of a
  previous run, which was then joined by `(frame, track_id)` with the new trajectory. It now
  deletes the `3b_Mascaras_`, `3c_Objetos_` and `7_AnalysisWindow_` files of the same base
  before recording.
