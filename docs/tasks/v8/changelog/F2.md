# F2 — class roles: CHANGELOG fragment and TEST_MAP lines

Branch `feat/v8-class-roles`. F7 merges this into `CHANGELOG.md` (8.0.0) and
`docs/testing/TEST_MAP.md`.

## CHANGELOG — 8.0.0

### Added

- **Class roles by name (ADR-009).** `core/detection/class_roles.py`: every class of a
  weight is `subject`, `arena`, `context` or `ignored`, stored by normalised class
  name (a retrain that inserts a class no longer shifts roles). One resolver,
  precedence project (only while its recorded weight sha256 matches) > weight
  registry > aliases > positional. Aliases never produce `context`, so zebrafish
  weights behave exactly as in 7.2.
- `weights_config.json` entries accept an optional `class_roles`, imported from the
  JSON shipped next to the `.pt` (e.g. `best_det_topdown_rat_v1.json`).
  `WeightManager.set_weight_class_roles`, `get_weight_sha256`, `sha256_for_path`,
  `openvino_cache_dir`, `openvino_cache_is_current`.
- `core/services/worker_model_resolution.py`: the weight the batch worker loads is
  resolved in the main process (`WorkerModelSpec`: path, type, sha256, OpenVINO
  export, class roles).
- Detectors capture the subject and context detections of each frame
  (`pop_class_observations()`, same one-shot contract as `pop_track_masks()`).
- Projects store `model_selection` (det/seg methods) at creation; new and migrated
  projects carry `analysis_window: None` and
  `model_overrides.class_roles` / `class_roles_weight_sha256: None`.
- Frozen 7.2.0 project fixture (`tests/fixtures/legacy/project_7_2_0/`).

### Changed

- Weights with class names, three or more classes and no class recognisable as the
  animal are refused (`ClassRolesUnresolvedError`, translated message) instead of
  tracking class 1 by position — live (`DetectorService`) and in the batch worker
  whenever the weight was resolved in the main process.
- Detectors track every `subject` class on one track-id axis (`in subject_ids`).
  Without an explicit map this is still exactly one class, the lowest animal id.
- With context classes, inference runs on the arena box widened by
  `model_selection.context_crop_margin_frac` (scope
  `context_inference_scope`) at `min(subject, context_min_confidence)`, re-filtered
  per role. Without context classes the crop and threshold are byte-for-byte 7.2.
- `apply_class_mismatch_fallback` ("small arena box = animal") only runs for weights
  whose classes nobody named.
- OpenVINO NMS is per class for models with more than two classes or with context
  roles; legacy two-class weights keep the agnostic NMS.
- OpenVINO cache folders are `<stem>_<sha8>_openvino_model` (and `_int8_`), and
  `metadata.json` records `source_sha256`. A 7.2 folder (no recorded sha) is
  re-exported once; until then the weight runs on PyTorch with a warning.

### Fixed

- The batch worker ignored the project's weight (`model_overrides.slot_weights` /
  `active_weight`) and always loaded the settings default — a project set up with a
  rat weight was processed with the zebrafish one.
- A retrained weight saved under the same file name reused the old OpenVINO export.
- The det/seg method chosen in the wizard was lost when the project was reopened
  (the global method was used); old projects recover it from `_wizard_metadata`.
- The multi-aquarium full-frame path tracked every class; with an explicit role map
  it now keeps subjects only.
