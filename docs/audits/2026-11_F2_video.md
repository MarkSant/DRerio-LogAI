# F2 — `core/video/` coverage front (TASK-087)

Scope: `src/zebtrack/core/video/` (15 files). Method: tests derive every expected value from
what the code returned (a scripted `cv2.VideoCapture`, a real `Detector` with a deterministic
plugin, a real `Recorder` writing to `tmp_path`), then a mutation block per module.

## Defects

None found, fixed or reported. Nothing in this front failed for a reason other than a wrong
expectation in the test itself.

## Observations (not defects — recorded so the next reader does not re-derive them)

| id | `file:line` | observation | status |
| --- | --- | --- | --- |
| F2-O-001 | `core/video/processing_worker.py` (`resolve_processing_offset` use in `_process_single_video`) | The pristine `config.yaml` has `processing_offset: 1`, so at `analysis_interval_frames = 3` a video's analysed frames are 1, 4, 7 (`frame_num % 3 == 1`), never frame 0. Correct and documented in `processing_interval_resolver`; the tests pin it because a "frame 0 is analysed" expectation is the first thing a reader gets wrong. | pinned |
| F2-O-002 | `core/video/processing_worker.py` (`_process_single_video`, calibration block) | With `aquarium_width_cm`/`aquarium_height_cm` at the TOP level of the task descriptor the worker builds a `Calibration` and hands it to `start_recording(calibration=...)`, which warps `x1..y2` into the rectified space. `CLAUDE.md` says no production caller supplies these keys, which is why raw pixels hold today. The new test `test_top_level_aquarium_dimensions_calibrate_the_recording` pins the behaviour so that the day a caller starts supplying the keys, the change of coordinate space is a visible test failure rather than a silent one. | reported |
| F2-O-003 | `core/video/processing_worker.py` (`_process_single_video`, `except ValueError` around `Calibration`) | `Calibration` never raises `ValueError` for a degenerate polygon (it logs `calibration.process.corner_detection_failed` and carries on with a zero ratio), so both `except ValueError` handlers are only reachable through a stubbed `Calibration`. The tests reach them that way. | reported |
| F2-O-004 | `core/video/progress_notifier.py:51`, `video_processing_service.py:126`, `video_context_factory.py:115`, `processing_worker.py:571` | Dead symbols listed by the A2 audit (`create_progress_callback`, `process_frame_source`, `_seek_to_frame`, `_format_subject`). Deliberately NOT tested; they account for the remaining ~50 uncovered lines of `progress_notifier.py` and `video_processing_service.py`. | skipped |
