# Every place production code assigns into a SHARED ``Settings`` sub-model.
#
# Format: <path relative to the repo root>::<sub-model>.<field>
#
# This file exists because of PR #524. The ad-hoc dialogs write the user's
# per-run choices into the shared ``Settings`` object and never restore them, so
# a flow that runs LATER in the same app session reads the earlier flow's
# numbers. On a real project that changed 7 of 9 analysis parameters -- freezing
# time, sharp turns, distance and speed -- with nothing in the UI or the logs to
# say so.
#
# The fix was made on the READER side: ``build_project_settings_snapshot``
# answers from a pristine baseline. This list guards the WRITER side, which was
# never closed: it fails when a NEW assignment appears, so the person adding it
# has to decide, in that PR, whether the readers of that field are protected.
#
# Adding a line is a real decision, not a formality. Before you add one, check
# that every reader of that field either goes through
# ``build_project_settings_snapshot`` or genuinely wants the live value.
# Removing a line is always safe.
#
# See tests/quality/test_shared_settings_mutations.py and
# tests/integration/test_flow_isolation.py.
